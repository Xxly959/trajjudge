# 讲解卡 08：配对 ΔAUC、判定点移动、ITT 敏感性与工作点迁移

> **对应里程碑**：Roadmap v3 模块 A（配对 `ΔAUC` 与 ITT 口径修正）& 模块 B（独立验证集与工作点阈值迁移）。
> **核心一句话（面试统一解释）**：
> 结构化架构没有凭空提升模型的辨别能力。它的价值在于：① 让通用裁判从基本失效变为可用（相对 `Comprehensive` 显著提升）；② 把判定点推到高召回区，并提供可调阈值；③ 每个判定都附带证据索引和越权标记，可以审计。

## 1. 为什么以前只看 McNemar 召回还不够？什么是配对 `ΔAUC`？

### 生活类比：两位安检员的“及格线”不同
假设有 100 个真坏包（失败轨迹）和 100 个真好包（通过轨迹），两位裁判 A 和 B 各自给每个包打一个风险分：
- **Accuracy** 把及格线卡得很严（不轻易抓人）：它只抓出 **27%** 的坏包，误杀好包 **8%**；
- **Evidence-Grounded** 默认及格线倾向宁严勿漏：它抓出 **63.7%** 的坏包，但误杀好包也升到了 **25.8%**。

如果你用 **McNemar 检验**直接比“两人在各自默认阈值下抓出来的坏包比例（`63.7%` vs `27.3%`）”，p 值会小到 `4.66e-10`——**但这其实是在不同误杀率下作比较！** 就像拿“抓 60 个贼但冤枉 25 个好人”去跟“抓 27 个贼只冤枉 8 个好人”比谁抓得多，一部分差异仅仅来自**判定点（Operating Point）**挪到了更高召回、更高误杀的区域，未必代表排序能力本身暴涨。

**配对 `ΔAUC`（Paired Delta ROC-AUC）怎么解决？**
- `ROC-AUC` 不看单一阈值，而是测量“随机抽 1 个失败轨迹和 1 个通过轨迹，裁判把失败排得比通过更靠前的概率”。
- **配对 `ΔAUC = AUC_A - AUC_B`** 在**同一批样本**上计算两个裁判的排序能力差，并用 **`scenario_id` 整簇 Bootstrap（B = 2000）**算出 95% 置信区间和双侧 p 值。如果 95% CI 跨越 `0`，就说明两者的全局排序辨别力没有拉开统计学显著差距——两者的主差异在于**默认判定点位置**与**分数粒度**。

### 什么是 `ITT`（Intention-to-Treat，意向性处理原则）？为什么要算？
- **问题**：`Grounded-GLMFlash` 在主队列上有 `16/200` 条运行报错（主要是早期未加 `schema_retries` 前输出截断 `finish_reason != stop`）。如果只看有效的 `184` 条（**complete-case**），万一报错的全是裁判最容易判错的难样本，剔除它们就会抬高分数（幸存者偏差）。
- **做法（ITT）**：不扔掉任何一条，把全部 `200` 条都纳进来；凡报错/缺失的行一律按**判失败、原始分 `score = 0.0`** 计入（这也是上线后遇到解析失败时保守拦截的安全兜底策略）。
- **P1-6 消融里的 ITT 启示**：在 60 条消融子集上，complete-case 下 `证据账本 (ΔAUC +0.157, p=0.012)` 和 `隔离槽 (+0.105, p=0.015)` 贡献显著，`Veto (+0.041, p=0.105)` 方向为正但 CI 跨 0；但因为 `full-v0` 早期有 `7/60` 条截断报错（多于 `no_quarantine`/`no_ledger` 的 `2/60`），ITT 下 `full` 的 AUC 从 `0.910` 降到 `0.837`（注：主队列中同一批 60 条轨迹 AUC 亦为 `0.910`，说明这 60 条子集本身偏容易，全量 200 条为 `0.755`）。所以汇报消融只讲**共同样本配对差**，不拿 `0.910` 充当全量指标，并主动标注 ITT 敏感性与子集难度差异。

## 3. 工作点（阈值）分析与验证集迁移怎么看？

为什么要对比 `Grounded` 和 `Accuracy` 的可调阈值能力？
1. **分数粒度差异**：在主队列 `200` 条上，`Grounded` 融合 Veto 分区与 `confidence_pass` 输出了 **`46` 个不同分值**，可以从容切出：
   - **严格档**（控误杀 `FPR ≤ 10%`）：冻结阈值 `score < 0.1294`，主队列召回 **`37.4%` (`34/91`)**、误杀 **`8.6%` (`8/93`)**；
   - **宽松档**（保高召回 `Recall ≥ 80%`）：冻结阈值 `score < 0.98125`，主队列召回 **`87.9%` (`80/91`)**、误杀 **`59.1%` (`55/93`)**；
   - **默认档**（`0.50`）：召回 **`63.7%`**、误杀 **`25.8%`**。
2. **`Accuracy` 的离散天花板**：`OpenJudge Accuracy` 只输出 `{1, 2, 3}` 三个整数：
   - 严格档 `score < 2.0`（阈值 `1.5`）：召回 `27.3%`、误杀 `8.0%`；
   - 次高档 `score < 3.0`（阈值 `2.5`）：召回最高只能到 **`54.5%`**（误杀 `18.0%`）；想拉到 `Recall ≥ 80%` 只能直接把阈值设为 `3.01`，**退化成 `100%` 全判失败、误杀 `100%`**！
3. **验证集迁移检验什么？**
   把主队列上选好并**事先冻结进 `PREREG_v3.md` §9** 的阈值**原封不动**套到 `100` 条独立验证集（`96% retail / 4% airline`，`93` 未见新场景 + `7` 已见场景）上，检验排序能否复现，以及跨分布后召回与误杀漂移了多少个百分点。

### `p1val (n=100)` 预注册验证集实测与阈值迁移结果
- **数据源**：`reports/p1_validation_v3.json`、`reports/operating_points_v3.json`、`reports/figures/fig8_operating_points_v3.svg`（Pre-registered Commit `54619c3ef4cc05c3a1259209e22d548883f9fa56`，`cohort_sha256: 6716de02...766c1`）。
- **有效数与配对 `ΔAUC`（诚实负复现）**：`Grounded 88/100`（`10` 504 + `2` 截断）、`Accuracy 98/100`（`2` 504）、`Comprehensive 78/100`（`15` 504 + `7` 超长截断）；三路无效行 fail/pass 均 exact 50/50 平衡。`Grounded vs Comprehensive` 配对 `ΔAUC` complete-case `-0.0337 [-0.273, +0.201], p=0.840 (n=69)`、ITT `+0.0144 [-0.138, +0.169], p=0.815 (n=100)`；`Grounded vs Accuracy` cc `+0.0344, p=0.539`、ITT `+0.0084, p=0.872`。
- **默阈工作点差异依然复现**：`Comprehensive` 默阈仅抓 `2/39 (5.1%)` / 误杀 `0.0%`，`Accuracy` `6/49 (12.2%)` / `6.1%`，`Grounded` `15/44 (34.1%)` / `22.7%`（ITT `42.0% / 32.0%`）。
- **两项可验证根因与 D36 公平对照排查**：① **主动补跑 `p1d33` 证伪“纯推理率混杂”假说**：在发现 `p1val` 下 `Comprehensive` 思考链率升至 `95.7%` 后，立即回主队列 200 条按相同 D33 参数补跑公平对照 `p1d33`（`89.5%` 思考链、均 `1647` tok），证实 `Comp-D33 vs pre-D33` 自身几乎无差（`ΔAUC +0.013, p=0.709` / ITT `-0.006, p=0.919`），反致 `53/200 (26.5%)` 失误与默阈 `2.9%`；公平对齐下主队列 `Grounded` 仍双口径显著领先（**cc `+0.133, p=0.038` / ITT `+0.127, p=0.024`**），全量合并 `300` 条 ITT 亦显著（**`+0.092, p=0.049`**）；② **真实根因 = 领域漂移（`airline 36.5% → 4%`）+ `gpt-4o-retail` 小样本方差（`n=69`, CI 宽 `0.47`）**：`retail → retail` 同域 `Grounded 0.677 → 0.638`、`Accuracy 0.599 → 0.597`，证实并无 D31 过拟合；同时在官方 `deepseek-flash (thinking=off)` 补齐 `DS-Comprehensive`（`198/200`, 默阈仅 `5.1%`, `AUC 0.588`）后，证实零思考底座上排序差不显著（`+0.039, p=0.427`），轻推理是解锁连续排序增益的必要条件。
- **冻结阈值跨分布迁移（`score < thr`）**：
  - `Grounded` 严苛 `<0.1294`：`37.4%/8.6% → 9.1%/2.3%`（召回 `-28.3 pp`）；默认 `<0.50`：`63.7%/25.8% → 34.1%/22.7%`（`-29.6 pp`）；宽松 `<0.98125`：`87.9%/59.1% → 77.3%/59.1%`（`-10.6 pp`）——误杀稳、召回随 `airline→retail` 难化下移，说明须分域重标定阈值。
  - `Accuracy` `{1,2,3}`：`<1.5` 与 `<2.0` 重合（`27.3%/8.0% → 12.2%/6.1%`）；`<2.5` `54.5%/18.0% → 32.7%/10.2%`；`<3.01` 在两队列均退化为 `100%/100%`。

## 4. 面试高频必答题（对应 Roadmap v3 F3，含验证集与盲区复核 6 问）

1. **为什么 McNemar 显示召回显著提升，但和 Accuracy 比 ΔAUC 不显著？**
   - 判定点不同；McNemar 只比较单一默认阈值下的二值命中率，而 `Accuracy` 默认阈值非常保守（误杀 3%–8%），`Grounded` 默认处在高召回区（误杀 26%）。AUC 看的是全阈值排序能力，DeepSeek-Flash 上同模型 `ΔAUC = 0.000` 恰恰证明了这一点。
2. **你的架构到底带来了什么，又没带来什么？**
   - 直接背本卡开头三句话：没有凭空提升模型对难题的辨别力上限；真正带来的是把几乎失效的 `Comprehensive` 拉入可用区、把判定点推到可调的高召回区（并解决 3 分制无法调至 80% 召回的离散限制）、以及每条判定可追溯到 `[index]` 证据与越权标记。
3. **D31 是在测试集上发现的，怎么保证没有过拟合？验证集为什么没复现相对 Comprehensive 的优势？**
   - ① D31 修复的是“多轮 `###STOP###` 终止态误判”和“7KB 政策截断”两个通用工程 bug，并无针对题面的硬编码；② 事前提交 Commit 1（SHA-256 冻结 `PREREG_v3.md §9`）后运行 `100` 条独立验证集，证实 `retail → retail` 同域 `Grounded` 仅 `0.677 → 0.638`、`Accuracy 0.599 → 0.597`，未见过拟合；③ 相对 `Comprehensive` 的 `ΔAUC` 未复现是因为双重混杂：域漂移（`airline 36.5% → 4%`）以及 `p1val` 统一开启 `D33 reasoning_effort=low` 将 `Comprehensive` 推理触发率从 `59.6%` 推至 `95.7%`（伴随 7 例超长截断使 ITT 仍仅 `0.598`），且默认工作点下 `Comprehensive` 仍只召回 `5.1%`。
4. **无效输出是怎么处理的？剔除会不会造成偏差？**
   - 同时报告 `complete-case` 与 `ITT`（无效行按判失败 `score=0.0` 计入）。主队列 `Grounded vs Comprehensive` 两种口径均显著；`Grounded vs Accuracy`（GLM-Flash）与 60 条消融在 ITT 下出现衰减，均已在报告和 `CLAIMS.md` 中诚实披露。
5. **P1-3 筛出的 `13/92` 条 DB 通过疑似盲区轨迹，能直接当实锤缺陷写进简历吗？**
   - 不能。`glm-5.3` 只作 Silver Label 候选初筛，目前已生成离线盲审包（`annotation/round3_review_packet/blindspots_13.md` 与 `claw48_disagreements_12.md`）与 `pending_human_review` 汇总脚本；在人工盲审完成并更新 CSV 前，只说明方法学可行性，不在简历中声称 `13` 条已人工确认为真盲区。
6. **为什么 Veto 的贡献在配对 ΔAUC 下不显著（`+0.041, p=0.105`）？那还要不要保留它？**
   - 要保留。原因有三：① 方向为正（complete-case `+0.041`, ITT `+0.064`），且实现仅是几十行纯 Python 逻辑，**API 成本和延迟增量都是零**；② 它的核心角色不是拉升全局排序，而是提供**确定性安全硬约束**（“只要存在 `unverified_claim` / `contradicted` / `omitted` 或 `unauthorized_side_effect`，LLM 绝不允许判通过”）；③ 在已经加了证据账本和隔离槽后，模型自己遵守规则的比例本来就很高，主队列中 Veto 覆写率只有 `3.3% (6/184)`（DeepSeek-Flash `1.0%`），所以统计差幅度天然有限，但能兜住关键的少数越权漏放。
